# Architecture

Wyatt's Games is a static website of puzzle games. Some games are printable
sheets you solve on paper; others are played in the browser. It is built with
[Astro](https://astro.build) and published to GitHub Pages at
https://joshrtay.github.io/wyattsgames/.

## How the pieces fit

```
hand sketches (scans/, not in git)
        │  designed and checked by hand + scripts
        ▼
puzzles/<game>/*.py ──► generate + verify each puzzle
        │
        ├─ printable games ─► .build/*.html ─► headless Chrome ─► public/<game>/sheets/*.pdf + *.png
        └─ interactive games ──────────────────────────────────► src/games/<game>/puzzle.json
                                                                        │
src/pages/<game>/index.astro ◄── src/games/<game>/game.ts ◄─────────────┘
        │  (layouts + shared styles + game interface)
        ▼
astro build ─► dist/ ─► GitHub Actions ─► GitHub Pages
```

There are two separate build steps on purpose:

- **`npm run puzzles`** (Python, run on your machine) creates puzzle content and
  proves each puzzle is sound. Its output is committed, so you only rerun it when a
  puzzle changes.
- **`npm run build`** (Astro) turns pages plus that committed content into the
  static site. GitHub Actions runs this on every push to `main`.

## Folder layout

| Path | What lives there |
|---|---|
| `src/games.ts` | The list of games. The home page builds its cards from it. |
| `src/pages/` | One Astro page per URL: `index.astro` (home) and `<slug>/index.astro` per game. |
| `src/layouts/Base.astro` | Every page's shell: `<head>`, fonts, global styles, airmail edges. |
| `src/layouts/GameShell.astro` | Frame for game pages: back link, title, game, then directions. |
| `src/styles/global.css` | Color and font tokens (light and dark), base styles, shared `.btn`, `.rules`. |
| `src/lib/game.ts` | The game interface (`GameHost`, `MountGame`, `createHost`). |
| `src/lib/paths.ts` | `url()` helper that adds the `/wyattsgames/` base path. |
| `src/games/<slug>/` | An interactive game's code (`game.ts`), styles and `puzzle.json`. |
| `public/<slug>/` | Static files served as-is: covers, sheet PDFs and previews. |
| `puzzles/` | Python scripts that generate, verify and render puzzles. `build.py` runs them all. |
| `puzzles/<slug>/sheets/` | Hand-written sheet HTML (for sheets that need no generator). |
| `scans/` | Original sketches. Ignored by git, because the repo is public. |
| `archive/` | Old copies kept during the reorganization. Ignored by git. |

## Pages and layouts

- **`Base.astro`** is the outermost shell. Shared styles come from
  `src/styles/global.css`; never copy tokens into a page.
- **`GameShell.astro`** wraps every game page. Slots:
  - default: the game board and its controls (the bulk of the screen)
  - `intro`: optional text under the title
  - `directions`: rule cards shown **below** the board (`<section class="rules">`)
- All internal links and asset paths go through `url()` from `src/lib/paths.ts`,
  because the site lives under `/wyattsgames/` on GitHub Pages.
- Styles for elements that a script creates at runtime must be global (a
  plain `.css` file imported by the page, or `<style is:global>`), scoped under a
  game-specific class such as `.line-maze`. Astro's scoped `<style>` only reaches
  markup written in the `.astro` file.

## The game interface

Every interactive game, whatever it's built with, plugs into the site the same way
(`src/lib/game.ts`):

```ts
export type MountGame = (root: HTMLElement, host: GameHost) => void | (() => void);

interface GameHost {
  id: string;
  load<T>(): T | null;      // saved progress (this browser only)
  save(state: unknown): void;
  clear(): void;
  solved(result?: Record<string, unknown>): void;   // fires "game:solved" on document
}
```

The page owns the markup and calls `mount(root, createHost("<slug>"))`. The game
draws into `root`, saves through the host (never `localStorage` directly), and
calls `host.solved(...)` when the player finishes. That keeps games swappable and
lets the site later react to a solve (unlock the next sheet, reveal a code)
without touching game code.

### Choosing a technology per game

| Kind of game | Use |
|---|---|
| Grid and logic puzzles, turn-based (e.g. line maze) | Plain TypeScript + SVG |
| Puzzles with lots of UI state (panels, undo trees, settings) | A React island (`@astrojs/react`) |
| Real-time, animated or physics games | Phaser (full engine) or PixiJS (2D rendering) |
| Printable sheets | HTML generated by `puzzles/`, rendered to PDF |

No framework is installed until a game needs one. Whatever it uses, the game still
exports a `MountGame` function.

## Puzzles

Each game's generator lives in `puzzles/<slug>/` and is responsible for proving its
puzzle is sound before writing anything:

- **escape-room-packet**: `letters.py`, `grids.py`, `fold.py` and `tree.py` assert
  each sheet has one solution and hands the right number to the next sheet
  (APPLE → 600 → 66 → 375,041 → 5,100 → 4,992 → 74,992). `equations`, `remainders`
  and `final` are hand-written HTML in `sheets/`.
- **line-maze**: numbers sit on the corners of a grid of squares; lines between
  them are walls, and the outer border (with an entrance and an exit gap) is drawn
  for the player. `generate.py` carves a random perfect maze of squares, derives
  the walls and corner counts, then a backtracking solver proves the counts (plus
  the rules "no wall loops" and "every wall connects to the border") allow only
  that maze, pre-drawing hint walls until they do. `--seed` picks the maze and
  `--size` its dimensions. `build.py` also makes a 5 × 5 practice board
  (`puzzle-practice.json`, page `/line-maze/practice/`). Both pages share
  `LineMazeBoard.astro` and `LineMazeRules.astro`, and `createLineMaze(puzzle)`
  turns any puzzle file into a `MountGame`.

`puzzles/build.py` lists every game's generators and sheet order. Sheets must render
to exactly one Letter page. Rendering needs Google Chrome and Python with PyMuPDF
(`pip install -r puzzles/requirements.txt`).

Print sheets use the same look as the site: Special Elite for letters, Courier
Prime for digits (so `1` never reads as `l`), and corner registration marks.

## Adding a game

1. Put the sketches in `scans/<slug>/`.
2. Write the generator in `puzzles/<slug>/`, verifying one solution. Register it in
   `puzzles/build.py` and run `npm run puzzles`.
3. Interactive: add `src/games/<slug>/game.ts` exporting `mount: MountGame`, plus
   its CSS. Printable: the sheets land in `public/<slug>/sheets/`.
4. Add `src/pages/<slug>/index.astro` using `GameShell`.
5. Add an entry to `src/games.ts` with a cover at `public/<slug>/cover.jpg`
   (1200 × 750). Set `listed: false` until it's ready for the home page.
6. `npm run dev` to try it, `npm run build` to type-check and build, then push.

## Deploying

`.github/workflows/deploy.yml` builds with `withastro/action` and publishes with
`actions/deploy-pages` on every push to `main`. The repository's Pages source must
be set to **GitHub Actions** (Settings → Pages → Build and deployment → Source).
