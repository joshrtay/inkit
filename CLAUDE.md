# Notes for Claude

Read [ARCHITECTURE.md](ARCHITECTURE.md) before changing anything; it is the source of truth for layout and conventions.

- Example puzzles live in `src/games/<type>/<n>.json`; make new ones with `npm run new` (`puzzles/grid/new.ts`), which proves each has exactly one solution. Every published puzzle must have exactly one solution, except panels (`solutions: "some"` in the genre), which need at least one: any line that obeys the symbols solves them, as in The Witness.
- The player (`src/game-types/grid/game.ts`) exports a `MountGame` and uses the `GameHost` (`src/lib/game-api.ts`) for saving and reporting a solve.
- `scans/`, `archive/` and `references/` are local-only (gitignored); the repo is public.
- **Grid engine changes reach the editors and the reader in the same change.** Whenever `src/engine` gains anything (a genre, a clue kind, a rule block or a rule setting, a style option, a mark, a puzzle field), add it to the editors and the sketch reader (`app/app/lib/read-sketch.server.ts`), give a new genre a name in `app/app/games/kinds.ts`, and write its guide in `src/guides/guides.ts` (rules with ✓/✗ pictures and a worked example; the site's /puzzles pages), then run `npm run guides` to check the pictures and solve the example. Creators can only change puzzles through the editors, so every type's editor must cover everything that type needs. The editor is paint (`/g/<id>/draw`): its converter, drawing → puzzle (a genre's profile and each part's reader in `app/app/sketchpad/to-puzzle.ts`), and back, puzzle → drawing (`app/app/sketchpad/from-puzzle.ts`, which also opens every puzzle made before paint); the tools and stamps that make each part (`MAKES` in `app/app/sketchpad/kit.ts`, the palette in `Sketchpad.tsx`); and the settings on This puzzle's rules (`PaintRules.tsx`, with the Rules and Look panels for admins). RYB (id `coats`, once Three Coats) is the exception: it keeps its figure editor, `FigureEditor.tsx` (`/g/<id>/edit`). These tables are typed against the engine's lists, so `npm --prefix app run typecheck` fails until they're updated: `PROFILES` (genres), `READERS` and `MAKES` (clue kinds and spec parts), from-puzzle's clue switch (clue kinds), and `app/app/editor/coverage.ts`'s `RULES`, `STYLE`, `MARKS` and `SPEC_PARTS` (and the reader's guides). Settings inside a rule and fields inside a clue aren't checked that way, so add those by hand. Every example must round-trip (`tests/unit/to-puzzle.test.ts`, and in the browser `tests/e2e/parity.spec.ts`). See `docs/grid-engine.md`, "The visual editor".
- Before committing: `npm run build` (type-checks the shared code), `npm --prefix app run typecheck` and `npm --prefix app test`; after engine changes `npm run selftest`; after editor changes `npm --prefix app run test:e2e` (needs the local site running or startable). Editing logic belongs in pure, unit-tested modules: the drawing's in `app/app/sketchpad/model.ts`, the puzzle's in `app/app/sketchpad/to-puzzle.ts`. Pushing to `main` deploys inkit.games once GitHub's tests pass.
